# UI Context — Lily Waist Line

## Design System Source

All UI styling must strictly follow `design.md` generated by Stitch AI.

This file does NOT define colors, typography, spacing, or visual identity.

It defines HOW the design system is used across the application.

---

## Theme System Note
All colors are defined as CSS custom properties in `globals.css` and mapped to Tailwind tokens via `@theme inline`. Components must use these tokens — no hardcoded hex values or raw Tailwind color classes like `zinc-*`.

## Theme Modes

The application supports:

- Dark Mode (Primary experience)
- Light Mode (Secondary experience)

Dark mode is default and preferred for luxury branding consistency.

Mode switching must not affect layout structure, only visual tokens from `design.md`.

---

## UI Principles

- Luxury-first eCommerce experience
- Minimal friction in user flow
- Conversion-focused design (not decorative UI)
- Product-first layout hierarchy
- Strong visual hierarchy for CTAs

---

## Page Structure Rules

### Home Page
- Hero section must lead directly to products
- Minimal text, strong visual focus
- Featured products prioritized above content blocks

### Product Pages
- Image-first layout
- Sticky purchase panel (desktop)
- Minimal distractions
- Fast add-to-cart flow

### Checkout Flow
- Minimal steps
- No unnecessary navigation
- Trust indicators visible at all times

### Admin Dashboard
- SaaS-style structure
- Data-focused layout
- No luxury styling here (functional only)

---

## Component Usage Rules

All components must be derived from:
- `components/ui/` (shadcn/ui base)

Rules:
- Do not rebuild primitives
- Extend only when necessary
- Keep UI logic separate from business logic

---

## Interaction Rules

- Animations must be subtle and functional
- No excessive motion
- Hover states must reinforce clarity (not decoration)
- Transitions must feel premium and smooth

---

## Layout Rules

- Use responsive mobile-first design
- Maintain strong spacing hierarchy from design system
- Avoid cluttered layouts
- Ensure clear visual focus per section

---

## Design Dependency Rule

If a UI decision conflicts with implementation:

> `design.md` overrides `ui-context.md` for visual decisions  
> `ui-context.md` overrides implementation for structural behavior

---

## Core Principle

UI must always serve:

- Conversion
- Clarity
- Luxury perception
- Fast user flow

Never prioritize decoration over usability.
